# meowdlm 0.0069 — 의미 슬롯(이해·생성 단일 선언) + 규칙 인덱스 전문화 처리량 실측

리뷰 §4-1 의 첫 단계(양방향 파이프라인 + 컴파일/인터프리터 처리량 비교)를 실행했습니다. 다만
**LLVM IR 방출은 이 트리 범위 밖**입니다. `emit-llvm.l` 은 `dlm_v0.0284` 컴파일러에 있고 meowdlm 은
Maru 인터프리터 위에서 돌기 때문에, 여기서 비교한 것은 "선언을 1회 전문화(규칙 인덱스)한 경로" 대
"매 호출마다 선언을 스캔하는 인터프리터 경로"입니다. 명칭을 정확히 유지합니다.

## 1. 의미 슬롯 — 한 선언에서 이해와 생성이 닫힌다

규칙 형식이 `(범주 => 인터페이스 (sem 술어 자식인덱스...) kids...)` 로 확장되었습니다. 노드는
`(node 범주 ifv 의미항 자식...)` 이고, 잎의 의미항은 단어입니다.

```lisp
(S => ((n $sn1) (p $sp1)) (sem clause 0 1) (Sbj ...) (VPred ...))
(Sbj => ((n $sn1) (p $sp1 3)) (sem np 0 1) (DET ...) (N ...))
(VPred => ((n $sn1) (p $sp1)) (sem vp 0 1) (V ...) (Obj))
```

생성 예: `an rain chases the cat` → `(clause (np an rain) (vp chases (np the cat)))`.

검사기는 노드의 의미항을 **자식 의미항에서 재구성해 대조**합니다.

| 항목 | 값 |
|---|---|
| 생성 트리 / 구조 재유도 / 선형화 | **150 / 150 / 150** |
| 의미항 변조(`(clause FAKE)`) 수용 | **0/150** |

즉 이해(문장→트리+의미)와 생성(트리→문장)이 **같은 선언**에서 나오고, 의미도 변조 불가 검사 대상에
들어갔습니다. 다만 의미항은 아직 **얕은 구조**(`clause/np/vp` + 단어열)이며, Horn 술어·논항으로의
연결은 미착수입니다.

## 2. 전문화 처리량 — 기대보다 작았습니다 (반증)

측정 조건: 고정 9문장 × 200회 = 1,800회 파싱, Maru 동일 바이너리, 시작 비용(97 ms) 차감, 3회 반복.

| 경로 | 총 시간(3회) | 파싱만 | 회당 |
|---|---|---|---|
| 인터프리터(매 호출 선언 스캔) | 1456 / 1434 / 1420 ms | ~1,337 ms | 0.743 ms |
| **규칙 인덱스 전문화** | 1208 / 1157 / 1218 ms | ~1,111 ms | **0.617 ms** |

속도 향상은 **약 1.20×(17% 시간 감소)** 입니다. 정확성은 동일합니다(양쪽 800 판정, 악성 1건 거부).

**해석**: 규칙 스캔 제거만으로 얻는 이득은 20% 수준입니다. 나머지 비용은 파싱마다 리스트를 새로
만드는 할당과 문자 리스트 기반 문자열 처리에 있습니다. 따라서 리뷰 §3-3 의 지적("해시/트라이 인덱스
와 기본 문자열 연산을 먼저 보강해야 CPU 우위 측정이 공정하다")은 **방향은 맞지만 우선순위가
다릅니다**: 인덱스만으로는 한 자릿수 배 개선이 나오지 않습니다. 다음 병목 후보는
(가) 파싱 중 할당, (나) 문자 리스트 문자열 연산, (다) 증명서·의미항 생성 비용입니다.

## 3. 반증·경계

- 이 측정은 **Maru 인터프리터 위의 전문화**입니다. LLVM IR 컴파일 이득은 측정되지 않았습니다.
- 9문장 고정 세트는 문장 길이 3–5로 짧습니다. 긴 문장에서는 스캔 비중이 달라질 수 있습니다.
- 의미 슬롯은 합성만 검사합니다. 의미의 **정오**(문장이 실제로 그 명제를 뜻하는가)는 검사 대상이
  아닙니다.
- 여전히 `fg-chk` 는 어휘 엔트리를 신뢰합니다.
