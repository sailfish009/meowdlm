# meowdlm 0.0065 — 비단말 인터페이스 자질 선언: `bind` 수작업 제거

0.0064 는 선언 하나에서 인식기·생성기를 뽑았지만, 명사구의 인칭 3 같은 값은 **터미널에 `bind` 를
직접 박아** 넣어야 했습니다(부모 제약은 터미널에서만 검사되므로). 이번 릴리스는 그 구멍을
**규칙 수준 인터페이스 선언**으로 메웁니다.

## 형식

```lisp
(범주 => ((특질 변수 [기본값]) ...) 아이범주...)
```

`(list 'Sbj '=> (list (list 'n '$sn1) (list 'p '$sp1 3))
       (list 'DET (list 'n '$sn1)) (list 'N (list 'n '$sn1)))`

- `(n $sn1)` — 내부가 바인딩한 값을 그대로 노출
- `(p $sp1 3)` — 내부가 비워두면 기본값 3 을 채운다(NP 주어는 3인칭)
- 부모는 자식의 인터페이스를 이름 공유로 그대로 받는다 → `bind` 불필요

즉 **선언에서 수작업 자질 주입을 없애고 같은 수치를 유지**했습니다.

## 시도했지만 철회한 것 (증명서 트리)

같은 선언에서 유도 트리를 뽑아 `certify.l` 식 증명서 검사를 붙이려 했습니다. 실패 원인은
구조적입니다: 생성기 항목을 `(subst words)` 에서 `(subst words trees)` 로 넓히면서 **자식 트리
목록과 규칙 아이 명세(`kids`)를 같은 자리에 섞어** 트리에 `(PRON (n $sn1) (p $sp1))` 같은
*선언 조각*이 들어갔습니다. `fg-chk` 검사는 그 결과 전부 거부(0/150)했고, 원인을 분리하기 전에
범위를 정리했습니다. 트리 축은 **미착수**로 남깁니다.

## 경계

- 인터페이스 기본값은 "내부가 비웠을 때만" 채웁니다. 내부가 **틀린 값을 바인딩**하면 검사가
  아니라 그대로 통과합니다(현재 `fg-if1` 은 바인딩 존재만 봅니다). 값 대조가 필요하면
  `(guard agree ...)` 로 명시해야 합니다.
- 기본값은 선언 작성자가 정합니다. 근거는 `lf-check` 의 NP=3인칭 가정이며, 이 가정 자체가
  언어학적으로 완전하지 않습니다(집합 명사 등).
- `a`/`an` 선택 규칙은 여전히 두 검사기 모두에 없습니다(`an cat` 수용).
