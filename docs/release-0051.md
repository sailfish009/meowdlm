# meowdlm 0.0051 — 학습 상태 저장/로드: Maru 네이티브 프리미티브만 사용

0.0050까지 학습 결과는 메모리에만 있었습니다. 이번에 **저장·로드·손상 거부·원자적 커밋**을 Maru
안에서 완결했습니다. 리뷰가 지적한 대로 이전 보고의 제약 4건은 **사실이 아니었고**, 그 프리미티브로
구현했습니다.

## 사용한 프리미티브 (실측)

| 기능 | 프리미티브 | 비고 |
|---|---|---|
| 직렬화 | `file-stream` + `print-all` + `dump-all` | 중첩 리스트·문자열 이스케이프 자동, `'(...)` 형태로 기록 |
| 무결성 | `file-read-byte` + `bitwise-and/xor` FNV-1a 32 | **load 이전에** 바이트 해시 검증 |
| 원자적 커밋 | `file-replace` (Linux rename) | 임시 파일 → 교체 |
| 정수 판별 | `long?` | `number?` 없음 → `long?` 사용 |
| 상호 재귀 | 전방 선언 `(define *x* 0)` | `st-load`가 런타임 로드 변수를 참조해야 해서 필요 |

## 측정 (Maru)

```text
SAVE gh=2692021089 jh=67718805
DETERMINISM 1                       (같은 입력 → 같은 해시)
LOAD (ok 9 3)                       (규칙 9개, 저널 3건)
COVER 5/100                         (복원 상태로 재도출)
REPLAY cover=3/100                  (저널의 retract NP 적용 → 도출 감소)
CORRUPT-RELOAD (reject 1109267194 67718805)   (해시 불일치 → load 생략)
```

## 판정

1. **저장·복원이 성립합니다.** `dump-all`로 쓴 `.l`을 `load`하면 규칙 9개·저널 3건이 그대로
   복원되고, 복원 상태로 도출(5/100)이 재현됩니다.
2. **손상 거부가 load 앞에서 동작합니다.** 페이로드를 다른 내용으로 바꾸면 FNV 불일치로
   `reject`를 반환하고 `load`를 시도하지 않습니다(구문 오류로 프로세스가 죽는 경로 차단).
3. **저널 재생이 학습에 반영됩니다.** `retract NP` 이벤트를 재생하면 도출이 5→3으로 줄어듭니다.
4. **결정적입니다.** 같은 상태를 두 번 저장하면 해시가 동일합니다.

## 경계

- FNV-32는 우발적 손상·절단 검출용입니다. 적대적 변조 방지는 외부 `sha256sum` manifest를 병행해야
  합니다.
- `file-replace`는 rename 래퍼라 동일 파일시스템 내 교체만 보장하고, `fsync` 내구성은 없습니다.
- 스키마는 비순환 리스트·심볼·정수·문자열로 제한합니다(공백 포함 심볼·순환 구조 제외).
- 스냅샷 압축(저널 임계 도달 시 세대 증가)과 이전 세대 폴백은 아직 배선하지 않았습니다.
