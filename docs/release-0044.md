# meowdlm 0.0044 — 웹 자료로 문법·품사를 "학습"할 수 있는가

질문: 영어 문법 규칙을 웹에서 받아 모델이 학습할 수 있는가. 답: **수집·적재·채택 판정은 되고,
규칙 자료의 수확은 0, 품사 자료의 수확은 도출 +18.4pp(판별력 손실 동반)**입니다.

## 웹 수집 (파이썬 허용 영역)

```text
tools/fetch/fetch_pos.py    dictionaryapi.dev 에서 품사·표제어  → cache/pos.json (554단어, 367 품사 확보)
tools/fetch/fetch_rules.py  Wikipedia(<chem> 블록) 구문 규칙     → cache/rules.json (3규칙)
tools/export_web.py         캐시 → data/web_pos.l / data/web_rules.l
```

`tools/fetch/`가 비어 있던 0.0043의 공백을 메웠고, 캐시가 있어 재현 시 네트워크가 필요 없습니다.
Maru 는 파일을 읽지 않으므로 `.l` 변환을 거쳐 적재합니다.

## 채택 실험 (Maru, 코퍼스 200문장)

| 팔 | 도출 | 역순 수용(음성) | 어휘 모호성 |
|---|---|---|---|
| A 기준(33공리, 유도 어휘) | 68/200 = 0.340 | 27/200 = 0.135 | 599 |
| B +웹 규칙 3개 | **68/200 = 0.340 (변화 0)** | 27/200 | 599 |
| C +웹 품사(367단어) | **100/200 = 0.500 (+16.0pp)** | 47/200 = 0.235 | 1210 |
| BC 둘 다 | 100/200 = 0.500 | 47/200 | 1210 |

코퍼스 500문장에서도 같은 방향: A 149 → C 241 (+18.4pp), 역순 62 → 132.

## 판정

1. **웹 구문 규칙 자료는 수확이 0.** Wikipedia 에서 기계적으로 뽑히는 규칙은 3개뿐이고
   (`S → NP VP`, `NP → DET NG`, `NG → A NG PP`), 셋 다 기존 33공리에 이미 함의되어 도출이
   1건도 늘지 않았습니다. 0.0034의 진단(구조 결핍 0)과 일치합니다.
2. **웹 품사 자료는 도출을 +16.0pp 올린다.** 사전 API 의 품사를 범주 후보로 추가하면 어휘가
   넓어져 문장이 더 도출됩니다. 접근만으로 얻는 이득이 실재합니다.
3. **그러나 판별력을 함께 지불한다.** 역순(음성) 수용이 0.135 → 0.235 로 오르고 모호성이
   599 → 1210(2.0배)이 됩니다. 도출/판별 비율은 A 2.52 → C 2.13 으로 나빠집니다. 0.0037·0.0039
   에서 측정한 1:1 교환비가 웹 자료에서도 그대로 재현됩니다.
4. 그래서 "웹 자료로 문법을 학습했다"는 표현은 **품사 축에서는 참, 규칙 축에서는 거짓**입니다.
   규칙 축의 천장은 자료 부족이 아니라 **이미 포화된 공리 집합**입니다.

## 경계

- Wikipedia 규칙 추출은 `<chem>` 블록만 대상으로 했습니다. 산문에 서술된 규칙은 미추출.
- 품사는 554단어 중 367단어만 확보(사전 미등재·오류). 표제어(lemma)는 받았으나 아직 쓰지 않았습니다.
- 역순 수용은 음성 프록시입니다(0.0038 의 내용어 셔플과 다른 지표). 절대값 비교는 팔 내부에서만.
- 코퍼스 200문장 표본. 500문장 결과는 문서에 병기.
