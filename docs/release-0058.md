## 정정 2 — 가지치기 2문장 손실의 원인

"게이트 순서(규칙→어휘) 문제"라는 제 가설은 반증됐습니다. V2(36공리)를 먼저 고정하고 TR200에서
가지치기해도 결과는 동일합니다: **tr200 75/75 보존, held800 267→265**. 손실은 보존 게이트가 본
표본(TR200) 밖 **HELD800에서의 표본 일반화 오차**입니다. 게이트 순서를 바꿔도 사라지지 않습니다.

## 정정 3 — 경험 저장소를 실제 추론 상태로 배선

이전 릴리스는 규칙 3개를 드라이버 상수 `*V2*`로 직접 선언했습니다. 이번 릴리스는
`src/meow/apply.l`을 추가해 **저장된 경험에서 상태를 복원**합니다.

```text
ap-build(exp, base-rules, base-lex)
  R 레코드 "adopt" → 규칙 추가 (rule_list 를 payload 로 저장)
  L 레코드 "removed" → 어휘에서 범주 제거 (제거 목록을 payload 로)
```

측정(저장 → 재로드 → 적용):

```text
STATE records=19 (L=15, R=4)  rules=36  amb=599→580
COV-BASE 286/1000 surf=2
COV-EXP  340/1000 surf=4
```

## 정정 4 — 생성 통과 4/15의 병목 분해

| 구분 | 문장 수 | 원인 |
|---|---|---|
| 통과 | 4 | affection, boxes(신규), dogs(신규), rain |
| OOV 실패 | **8** | listen, airborne, shh, first, observe, actually, delay, moved (9토큰) |
| 무OOV 구조 실패 | 3 | greeting(전치사 연쇄), humans(무접속 이중절), nonsense_questions(조건절) |

현 어휘에서 15문장의 이론 상한은 **7/15**입니다. 14/15를 얻으려면 OOV 8문장을 어휘로 편입하고
구조 규칙 3개를 더해야 합니다. 그리고 `surface.l`의 `s-try`는 아직 `syn-accepts`를 호출하지 않아
(OOV 4건 통과가 그 증거) 생성-검사 루프는 다음 릴리스입니다.
