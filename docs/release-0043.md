# meowdlm 0.0043 — 단서 추출 이관(선행 조건) + OOV 매핑 실험(음성)

0.0042가 밝힌 병목은 **단서 색인**이었습니다. 이번에 그 선행 조건인 `induct.l`(원문 → 토큰/어간/
단서)을 Maru 로 옮기고, 그 위에서 OOV 매핑을 다시 측정했습니다.

## 1. 단서 추출 이관 — 참조와 문자열 일치 170/170

```text
src/meow/induct.l    tokens([a-z']+ → morph), STOP 필터, 내용어 1·2·3gram
morph 규칙           아포스트로피 제거 → -ies→y → -ing/-ed/-es/-s 제거 → 중복 자음 축약
```

파이썬 `induct.cues()` 출력과 **170/170 문자열 일치**(공백 포함 완전 일치). 이관 중 잡은 버그 2건:

```text
- i-tail-eq? 가 접두를 비교하고 있었다(꼬리가 아니라) → -ing 제거가 전혀 안 됨("morning" 유지)
- i-morph 가 문자 목록을 반환해 string-length 에서 실패 → 문자열 반환으로 고정
```

## 2. OOV 매핑 + 단서 재추출 — 음성

문자 2-gram 자카드로 OOV 단어를 기존 어휘에 사상한 뒤 **단서를 재생성**해 판정했습니다
(0.0042에서는 단서 문자열 치환만 해서 판정이 변하지 않았습니다).

| 팔 | OOV 97건 | 정상 73건 |
|---|---|---|
| A 정확 일치(기준) | **44/97 = 0.454** | 61/73 = 0.836 |
| 매핑 τ=0.10 (127쌍) | 38/97 = 0.392 | 61/73 = 0.836 |
| 매핑 τ=0.20 (109쌍) | 41/97 = 0.423 | 61/73 = 0.836 |
| 매핑 τ=0.30 (57쌍) | 41/97 = 0.423 | 61/73 = 0.836 |

**매핑은 OOV 구간에서 −3.1~−6.2pp 해롭고, 정상 구간은 불변**입니다. 원인은 매핑 품질입니다:

```text
sunshine → machine (자카드 0.25)
floof    → floor   (자카드 0.43)
```

문자 n-gram 근접은 형태가 비슷한 **무관한 단어**를 고릅니다. 치환은 진짜 단서를 지우고 잡음을
넣으므로 질량이 흐트러집니다. 자카드 임계를 올리면(0.30) 매핑 수가 줄어 손실도 줄지만 이득은
남지 않습니다.

## 판정

- **가설 "문자 근접 매핑이 OOV 흡수 벽을 깬다" → 기각**(이 코퍼스·이 임계 범위에서).
- 단서 추출 이관 자체는 성공했고, 이제 OOV 실험이 **판정 경로에 도달**합니다(0.0042의 차단 해소).
- 남은 대안은 어휘 의미 자원(동의어 사전) 또는 분포 학습(코퍼스 동시출현 벡터)입니다. 문자
  유사도만으로는 부족하다는 것이 이번 측정의 결론입니다.

## 경계

- 코퍼스는 여전히 어휘 554·고유 입력 201입니다. 리뷰 기준의 5,000+/OOV 30% 규모 실험은 미착수.
- 매핑은 2-gram 자카드 한 종류입니다. 편집거리·접두 일치는 미측정.
- 정상 구간 불변은 그 구간에 OOV 토큰이 없기 때문이며, 매핑이 정상 판정을 해치지 않는다는
  증거로만 읽어야 합니다.
